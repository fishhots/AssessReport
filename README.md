# 教学质量报告智能体

Vue 3 + TypeScript + Spring Boot + Python LangChain/LangGraph。用户上传资料、勾选固定报告章节、选择一个模型，生成一份完整 Word：原模板内容 → 第九章个性化报告 → 可选的第十章用户主题报告。

完整的工作流、Skill、提示词、工具和实施顺序见 [智能体开发流程](docs/智能体开发流程.md)。已实现执行链路，并完成原始问卷预统计、主题结构与 Word 排版更新；离线测试验证工具循环、章节范围、任务状态和输出，真实 DeepSeek 已复测第三章。整份成文质量与尚未覆盖的复杂指标仍需验收，详见 [报告对比与优化记录](docs/报告对比与优化记录.md)。

2.1版新增专业/学院分组、课程评价统计及有数据小节的漏项补写。正式Word使用直接成文，不展示逐段引用和资料来源附录；内部保留全部来源与校验。最新逐章对照、空项原因及验证范围见 [最新报告对比与优化](docs/最新报告对比与优化.md)。

## 功能与范围

- 支持邀请码注册、账号密码登录和自动登录（30天）。注册填写用户名、账号、密码、邀请码，默认邀请码为 `appmath`；账号不区分大小写，密码至少8位。资料库、报告记录、任务缓存和模型配置按登录用户独立保存，下载、修改、删除也校验所属用户。
- 唯一模板是“毕业生培养质量评价报告”，保留原报告九项章节名称和顺序，默认全选，也可部分输出。
- 正式报告追加“第九章 个性化报告”，包含专业结构与培养定位、毕业学习成果、课程与实践教学体系三个维度。
- 工作台可添加主题章节，填写题目与分析要求，在个性化报告后追加第十章；主题参数随任务保存和重试。未填写主题时不生成第十章。
- 分类上传 XLSX、XLS、CSV、PDF、DOC、DOCX、TXT；支持 Word 旧格式解析桥接、文本证据定位、表格频数/分组/数值统计与有来源的比例计算。
- 六个项目业务 Skill、十个业务工具、分层提示词、结构化章节、引用和数值出处校验。资料没有固定的必传清单，每章都基于本次已上传资料取证；不足的部分跳过，并在文内列出资料缺口，保留原章节名称。
- 支持 Qwen、DeepSeek、GLM、GPT、Claude、Gemini 的配置和统一调用。模型页的“已配置”表示必要配置齐全；可设置自动适配、启用或关闭额外深度分析，以及思考强度和适用模型的预算。“测试连接”检查当前执行路径的思考/工具能力及结构化输出，只发送固定测试文本。
- 任务详情提供开始生成、进度、终止生成、继续生成和完整报告下载（历史两份文档仍可下载）；报告记录支持删除。删除会移除该任务的记录、输出和执行缓存，已上传资料与模型配置会保留。
- Word 复用人工模板提取的原生封面、页面、字体、二至四级标题编号及表格样式，保留109个有效指标标题和154项原图表位置。原报告中的两个空白标题占位不输出。本机安装 Word 时自动更新目录页码，其他环境保留可更新的目录字段。支持饼图、环形图、折线图、柱形图、条形图、堆积图、双向条形图和散点图；长专业列表拆成续图，表格跨页重复表头。
- 第一至第七章的大标题与“本章小结”之间插入模板背景概括；“核心发现”的9个主题用“原主题名：本次资料支持的简短结论”组成蓝色标题。原小节路径和自动编号保持不变，正文不重复标题结论。背景不含校本成效，数据不足的主题不套用人工报告结论。
- 目录中的“核心发现”只展示章标题和页码，正文下级标题保留；一级目录页码使用右对齐点线，更新整个目录后仍生效。
- 第1、5、6、7章的36张表按人工版逐表固定表头、分组、列宽和届次列。缺少历史数据保留“—”，有真实历史资料时分别统计填入；不拆分两届合并指标。课程表按两类对口人群独立统计，实践满意度排除“未参加”，合并格只显示一次名称。详细差异及修改入口见 [表格对比与修正记录](docs/表格对比与修正记录.md)。
- 已登记样例 114 幅图、40 张表，恢复原二、三级主题和图表位置。除学院/专业聚合图，问卷单选、多选拆列、评价矩阵、实际升学与满意度分组也可自动统计和绑定原图表。只有当届数据时展示当届柱图并说明无法比较趋势。目录包含可更新的 Word TOC 字段和章节跳转，缺图清单集中在补充说明。范围及限制见 [图表开发说明](docs/图表开发说明.md) 和 [报告对比与优化记录](docs/报告对比与优化记录.md)。复杂能力达成算法、外部基准和正式专业名单仍须有依据。
- 联网检索：智能体可按学校官网域名与主题模板自动检索领导讲话、战略规划等公开信息，结果自动形成库存档并登记进个人资料库，后续报告任务直接复用；任务内可开启自动预取，DeepSeek 无工具思考路径同样可用。详见 [联网搜索模块](docs/联网搜索模块.md)。

## 首次准备

环境：Python 3.11+、Node.js 22.16+、JDK 17+、Maven 3.6.3+。

```powershell
.\setup-agent.ps1
# 如 Python 不在 PATH：
# .\setup-agent.ps1 -PythonExecutable 'C:\Python312\python.exe'
```

脚本创建独立 Python 环境、安装锁定依赖，首次复制 `agent-service/.env.example` 为 `.env`，已有配置会保留。启动服务后打开网页“模型设置”，点击对应模型，填写模型名称、接口基础地址（Base URL）和 API Key，按需填写额外 JSON 参数，再点击“保存配置”或“保存并测试”。

模型名称、业务空间、地域和接口地址以账号控制台为准。GPT 官方使用 Responses API，中转使用兼容聊天接口；Claude 使用 Anthropic 原生接口，其余使用兼容聊天接口。GPT、Claude、Gemini 可在模型设置中选择中转或官方方式，分别保存配置，参见 [国外模型中转与官方调用](docs/国外模型中转与官方调用.md)。地址填写基础地址，不要追加 `/chat/completions`、`/responses` 或 `/messages` 请求路径。

各模型配置均从网页编辑，无后端预设的模型名称、接口地址和密钥，也不再读取旧版的 `QWEN_API_KEY` 等供应商环境变量。密钥通过后端发送到 Python 服务，并加密保存在本地 SQLite；查询配置仅返回是否保存及固定掩码，留空保存会保留原密钥，填写新密钥会替换。密钥不保存到浏览器 localStorage、任务快照或提示词。报告任务和连接测试创建模型客户端时读取最新配置，正在执行的任务继续使用其已创建的客户端。修改模型配置无需重启服务；服务端口、超时和内部认证配置仍在 `.env` 中设置并需要重启生效。

DeepSeek 官方 API 的配置示例（2026-10-03）：模型名称 `deepseek-flash`，接口地址 `https://api.deepseek.com`，章节深度分析选“自动适配模型”，额外参数可留空。分析阶段开启思考，结构化成文阶段关闭或降低思考；两步均为独立的无工具请求，避免强制工具调用与思考历史回传的限制。已有额外参数保留在配置中，请求的思考参数由当前阶段适配，不必手写关闭思考的 JSON。支持范围与参数映射见 [报告扩展与思考模式](docs/报告扩展与思考模式.md)，模型名称以 [DeepSeek 官方文档](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/) 为准。

连接测试实际验证固定文本的思考/工具调用和结构化返回，不发送上传资料。测试失败会分别提示认证、API 余额/额度、临时限流、网络连接、接口参数、模型不存在、平台服务和结构化输出问题。`.logs/agent-error.log` 记录安全的错误类别、HTTP 状态和测试阶段，不记录原始响应或密钥；后续排查应先依据错误类别，避免反复测试余额或额度不足的账号。

普通模型最多四轮取证，通过 LangChain create_agent/ToolStrategy 完成成文。思考模型采用程序预统计及检索 → 深度分析 → 独立请求生成 SectionDraft JSON，两步均不携带工具或历史思维链。复杂章按原指标逐项展开，最多96段；格式错误最多修订两次。内容校验失败时只修订出错的段落或表格，并携带原引用证据和具体待核实数值，已通过内容由程序保留。两次修订后仍不符合证据要求的部分会被剔除，保留可核实内容并注明缺口，继续其他章节和个性化分析；单章未返回合规结构时保留原标题并注明本次未完成。认证、余额、网络、时间或调用预算错误仍作为执行错误提示，避免误报为资料不足。已准备的图表由程序校验并附加，模型不负责填写自动图表的图片编号。每次任务在 `model-calls.json` 中保存章节、轮次、阶段、工具名称及思考消耗/是否观测到思考，不保存密钥或原始模型响应。引用ID和图表编号不作为统计数值参与校验，真实数值和引用校验仍执行。

可选 `ASSESS_SERVICE_TOKEN` 用于 Spring Boot 与 Python 之间的认证。启动脚本会读取此值给后端设置 `AGENT_SERVICE_TOKEN`；手动分别启动时需要给后端设置相同值。

## 联网搜索（可选）

默认关闭，不影响原有报告流程。启用步骤：

1. 在「模型设置」保存 **DeepSeek 官方 API Key**（联网搜索复用这把密钥，无需再填一次）。
2. 打开左侧「联网检索」，填学校名称与官网域名（如 `bistu.edu.cn`），选择主题，点「预览检索指令」确认搜索式，再点「执行检索并入库」。
3. 抓到的网页会自动归档，并以 `.txt` 资料出现在「资料库」；报告工作台勾选即可复用，无需人工预先收集领导讲话与规划文件。
4. 也可以在工作台勾选「本次启用」，让报告生成前自动检索，并把官网正文作为可引用证据加入本次任务。

只需特定年度的资料时，在「联网检索」或工作台填「资料起始年份 / 结束年份」（可填 `2025` 或 `25`）；**起止填同一年即只获取该年资料**。年份作为检索关键词参与搜索，**不使用时间操作符**（学校官网页面大多不标发布日期）；归档前按发布时间、标题与 URL 判定年份，明确落在区间外的页面会被排除，无法判定年份的页面默认放行，可取消勾选「包含未标注年份的页面」改为严格排除。

Search / Fetch 按成功请求次数单独计费；相同指令在缓存期内直接复用归档，不联网不计费。指令字段、接口契约、安全边界与排错见 [联网搜索模块](docs/联网搜索模块.md)。

## 启动与停止

Windows 中可以直接双击项目根目录的 **一键启动.bat** 和 **一键停止.bat**。启动会准备缺少的项目依赖、构建后端、启动三个服务，并在全部就绪后打开浏览器。重复启动已运行的系统会直接打开网页；两个按钮共用运行锁，避免同时启动多份服务。首次使用仍需安装前文列出的 Python、Node.js、JDK 和 Maven。

启动或停止失败时窗口会保留错误提示；运行日志在 `.logs/`。停止只操作本项目记录的服务，不删除资料或模型配置。也可以继续使用 PowerShell：

```powershell
.\start-dev.ps1
.\stop-dev.ps1
```

启动脚本构建后端，在后台启动三个服务，默认地址：

| 服务 | 地址 |
| --- | --- |
| 前端 | http://127.0.0.1:5173 |
| Spring Boot | http://127.0.0.1:8080/api/health |
| LangChain 服务 | http://127.0.0.1:8000/health |

日志保存在 `.logs/`。停止脚本只停止本项目记录的进程。更改默认端口或存储位置时，应分别启动并同步代理、`AGENT_BASE_URL` 和 `ASSESS_UPLOAD_ROOT`：

```powershell
# 终端一，从项目根目录执行
cd agent-service
.\.venv\Scripts\python.exe -m assess_agent

# 终端二，从项目根目录执行
cd backend
mvn spring-boot:run

# 终端三，从项目根目录执行
cd frontend
npm install
npm run dev
```

前端开发服务代理 `/api` 到 Spring Boot。部署静态产物需配置反向代理。首次打开网页需注册后登录；未登录时无法访问业务接口。刷新保留当前页面，勾选自动登录可在会话有效期内恢复登录。

## 账号与用户空间

不需要部署 PostgreSQL。账号、会话使用本地 JSON，任务和模型配置继续使用嵌入式 SQLite，业务文件按用户 ID 分目录保存。用户名用于页面显示，账号用于登录；不同用户可配置不同的模型密钥和接口。

密码仅保存 PBKDF2 加盐哈希。登录凭据使用 HttpOnly、SameSite=Lax Cookie，服务端只保存其哈希；未勾选自动登录为浏览器会话 Cookie、服务端最长12小时，勾选后最长30天。退出登录会撤销当前会话。浏览器草稿按用户 ID 保存，密码和模型密钥不写入 localStorage。退出或登录失效后会清理页面中的资料、报告和模型状态；退出不终止后端报告任务，重新登录后可继续查看进度。

旧版单用户资料不会自动归属新注册账号。迁移时应明确指定所属账号，核对资料、报告下载和模型配置后删除旧目录与迁移副本，只保留用户目录中的有效数据。新账号使用独立的空工作空间。升级需要重启 Java 后端和 Python 智能体；有正在生成的任务时应先等待任务结束。

邀请码可通过 `ASSESS_INVITE_CODE` 调整，默认 `appmath`。访问域名与代理部署时，可通过 `ASSESS_ALLOWED_ORIGINS` 指定额外允许的完整网页来源（逗号分隔）；同来源请求默认允许。HTTPS 部署可设置 `ASSESS_COOKIE_SECURE=true`，浏览器只在 HTTPS 请求中发送登录 Cookie。内部 Python 服务继续使用 `ASSESS_SERVICE_TOKEN`，仅供 Java 后端访问，不对浏览器开放。

## 数据与任务恢复

| 位置 | 内容 |
| --- | --- |
| `backend/data/auth/accounts.json` | 用户信息、密码盐和密码哈希 |
| `backend/data/auth/sessions.json` | 登录会话哈希、用户 ID 和有效期 |
| `backend/data/users/{用户ID}/workspace.json` | 该用户的文件索引、任务参数及同步后的状态 |
| `backend/data/users/{用户ID}/uploads/` | 该用户按资料 ID 保存的原始上传文件 |
| `agent-service/data/users/{用户ID}/jobs.sqlite3` | 该用户的执行状态、尝试次数、错误及输出清单 |
| `agent-service/data/users/{用户ID}/model-config.sqlite3` | 该用户的模型配置及加密后的密钥 |
| `agent-service/data/users/{用户ID}/model-config.key` | 该用户的模型密钥加密文件，需与配置数据库一起备份 |
| `agent-service/data/users/{用户ID}/jobs/{任务ID}/attempt-{次数}/` | 该用户的证据、草稿、DOCX 和结果清单 |
| 浏览器 localStorage 中的 `assess-report-draft:{用户ID}` | 该用户的工作台草稿 |

SQLite 为嵌入式数据库，不需要部署 MySQL。系统不会自动创建完整数据备份。若管理员另外备份，应包含两个 `data/` 目录，并使用 SQLite 备份接口或先停止服务。`Doc/` 原始需求和样例不自动导入、不作修改。

任务缓存采用以下规则，适用于本地运行和服务器部署：

- 上传资料在所属用户资料库中只保存一份；解析资料不写入各阶段快照，阶段记录仅保存简短进度。
- 未完成的章节、修订进度和公开模型回答使用压缩 JSON 检查点。继续生成先合并最新的有效检查点，任务结束后删除旧尝试目录；资料解析和图表可从原始资料重建。
- 正文已完成但 Word 导出失败时，保留一份压缩证据、已校验正文及必要图表，继续生成只导出、不调用模型。
- 任务成功且最终文件通过 SHA256 校验后，只保留最终 Word 文件，删除解析缓存、检查点、图表源文件、审计正文、模板副本和旧尝试目录；统计信息与下载校验值保留在任务数据库中。服务启动时也会清理历史成功任务。
- 清理只针对已经结束的任务；运行中的任务、用户资料、账号和模型密钥均保留。Docker 每个服务日志最多约10 MB，避免长期累积。

任务状态：`DRAFT → QUEUED → RUNNING → SUCCEEDED`；执行失败为 `FAILED`，服务重启时未完成任务为 `INTERRUPTED`。资料不足仍可生成完整文档，完成提示会提醒查看文内资料缺口。每份资料不必对应某一章节，至少需有一份可读取的文本或数据。

排队任务点击“终止”会立即成为 `CANCELLED`。运行中的任务进入 `CANCELLING`，不再发起后续模型或工具调用。千问及 GPT、Claude、Gemini 中转使用流式传输，在接收下一片段时检查取消并关闭连接；其余调用等待当前请求结束或超时。终止中的任务不能删除或继续生成；终止完成后可以“继续生成”或“删除记录”。执行和连接测试均关闭 SDK 自动重试，避免隐式重复调用。

正文已全部完成并通过校验、仅 Word 导出失败时，“继续生成”直接恢复已保存的正文、个性化报告、主题章节和图表，继续导出；不创建模型客户端、不重新调用模型，也不要求重新上传资料或重新配置密钥。导出程序更新不会使已完成正文失效。本次恢复的 `usage` 为零，原生成用量单独保存在 `previousUsage`；`resume.mode=export` 表示仅恢复导出。如果恢复文件损坏或不匹配，系统明确报错，不会悄悄转为付费重写。新版保存 `export-checkpoint.json`；旧版已完成校验的阶段快照及导出审计也支持恢复，包括本次 GLM 任务。

正文尚未完成时，“继续生成”产生新的尝试目录，先核对资料内容、模型名称/接口/思考参数、用户要求以及提示词、Skill、模板与程序版本；一致时复用已完成并再次通过内容校验的章节，以及已完成的公开分析结果。未完成章节的正文、修订轮次、已完成的补写小节和待修订的补写内容也会保存，恢复后重新核验，只调用尚未完成的步骤。图表在当前目录重新绘制。输入或写作规则变化时重新生成，不会混用不匹配的旧内容。未完成任务的复用记录压缩保存在 `checkpoints/`，不保存密钥或模型私有思维链。任务数据库中结果的 `resume` 列出复用章节、未完成正文及分析次数，`usage` 统计本次实际发起的调用；历史尝试的已计费用量不会被再次计入本次。尚未完成正文且没有兼容检查点的旧任务需要重新生成。

独立分析步骤返回 `MODEL_UNAVAILABLE` 时，直接根据同一批已核验资料进行正文撰写，并在调用日志记为 `analysisFallback=verified_evidence`，不重复请求分析。正文请求失败仍报错并保留进度；认证、余额、限流和超时不会被当作分析结果继续使用。详见[中断后的正文与补写恢复](docs/中断后的正文与补写恢复.md)。

自动目录和页码更新在独立工作副本上运行，最多等待90秒；超时只清理本次新建且身份匹配的 Word 进程。更新失败仍可导出完整正文，任务提示“目录页码需在 Word 中更新”，可在 Word 中更新目录字段。用户已打开的 Word 进程不会被批量关闭。

千问的分析与正文均流式接收，并获取最后一片段的 Token 用量。生成请求的连接超时最多30秒，连续无数据等待为 `max(ASSESS_MODEL_TIMEOUT, 180)` 秒，单次流式调用累计最多600秒，同时遵守总任务时间限制；连接测试保持30秒以内。超时会停止任务后续调用，不会自动重发。未收到平台用量时，调用日志标记 `usageStatus=unknown`，不能视作零消耗。模型在断开前处理的输入、已生成的输出仍可能计费，实际费用以平台账单为准。参见[千问流式输出与计费说明](https://help.aliyun.com/zh/model-studio/stream)及[本次排查记录](docs/千问超时与继续生成.md)。

GPT、Claude、Gemini 中转的分析、正文、补写和修订统一采用流式传输，默认单次最多等待600秒，连接测试默认60秒。可分别通过 `ASSESS_RELAY_MODEL_TIMEOUT` 和 `ASSESS_RELAY_TEST_TIMEOUT` 设置，重启智能体后生效；详见 [中转等待时间](docs/国外模型中转与官方调用.md#中转等待时间)。

扫描 PDF 暂未接入 OCR。带百分号或单位的数值列不会作为普通数值直接汇总；缺少表头或存在多层合并表头时应检查识别结果和口径。证据校验是确定性规则检查，真实验收还需核对指标定义、事实归属和建议质量。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/register` | 用户名、账号、密码和邀请码注册 |
| POST | `/api/auth/login` | 账号密码登录，`rememberMe` 控制自动登录 |
| GET | `/api/auth/me` | 获取当前登录用户 |
| POST | `/api/auth/logout` | 撤销当前登录会话 |
| GET | `/api/health`、`/api/catalog` | 服务状态和模型配置 |
| GET/POST | `/api/materials` | 资料列表/分类上传 |
| GET | `/api/web-search/status` | 联网搜索配置状态与主题模板 |
| POST | `/api/web-search/preview` | 展开定向检索指令，不联网 |
| POST | `/api/web-search/run` | 执行检索并自动登记归档资料入库 |
| GET | `/api/web-search/archive` | 官网资料归档库 |
| POST | `/api/web-search/archive/sync` | 批量同步未入库归档 |
| DELETE | `/api/materials/{id}` | 删除未被任务引用的资料 |
| GET | `/api/materials/{id}/download` | 原始资料下载 |
| GET/POST | `/api/reports` | 查询/保存报告任务 |
| GET | `/api/reports/{id}` | 任务详情及最新状态 |
| POST | `/api/reports/{id}/run` | 开始生成或重试失败/中断/已终止任务 |
| POST | `/api/reports/{id}/cancel` | 终止排队或运行中的任务 |
| DELETE | `/api/reports/{id}` | 删除已结束或未开始的报告记录，保留上传资料 |
| GET | `/api/reports/{id}/outputs/{kind}` | 新任务 `kind=report`；历史 `diagnosis` 下载保持兼容，均校验 DOCX 完整性 |
| POST | `/api/models/{id}/test` | 固定文本的思考/工具与结构化输出测试 |
| GET/PUT | `/api/models/{id}/config` | 查询脱敏配置/保存模型配置，`id` 为六类模型之一 |

资料类别为 `DATA/SPEECH/REFERENCE`，模板固定为 `graduate`。创建任务参数沿用前端契约，`chapters` 使用完整原章节名称。选填 `customTopic: {title, requirements}`；题目限100字符、要求限4000字符。模型配置新增 `reasoningMode`（auto/on/off）、`reasoningEffort`（low/medium/high）和 `thinkingBudget`（1024–16000）。Python 内部 API 为 `/models`、`/jobs`、`/jobs/{id}/retry`、`/jobs/{id}/cancel`、`DELETE /jobs/{id}`、`/jobs/{id}/artifacts/{kind}`，由 Spring Boot 访问。
