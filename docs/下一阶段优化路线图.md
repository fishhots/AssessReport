# 教学质量报告智能体下一阶段优化路线图

本路线图整合前两轮麦可思反馈、解读规范与案例，以及10月20日会议纪要。第一阶段以“独立专题能完整回答问题、统计正确、建议有校本依据”为验收主线；官网检索、跨年复用、私有模型和多源诊断按各自依赖推进。以下均为待实施计划。

## 一、先修复已确认的运行问题

| 问题 | 实施方向 | 针对性验收 |
| --- | --- | --- |
| 多届资料解析超限 | 预检文件、工作表行数和展开量；按届次、工作表分批统计，避免重复展开宽表字段和整表明细；超限时说明命中的限制与位置 | 同一批双届样例可分别计算并在口径一致时比较；超限样例明确指出原因，不能静默截断 |
| 千问任务超时 | 分开记录任务总时限、单次调用时限、阶段及耗时；复用已完成统计和章节，按需修订 | 复现总时限错误，确认可继续执行且已校验内容不会无故重跑 |
| GPT 流式异常 | 保留安全的上游错误分类、请求编号（接口提供时）、失败章节和耗时 | 能区分上游流式异常与本地任务超时，不将未知原因自动归类为限流或中继不稳 |

服务器已有日志确认：千问样例在约60分钟后触发任务总时限；GPT 样例的上游状态未知；部分任务在资料解析阶段触发限制。不能把三者归为同一故障。日志可限量保留，缓存清理时保留必要诊断元数据，不保存密钥、完整请求或学校原始资料。

## 二、以独立专题验证专业解读

完整报告继续采用现有固定模板及章节结构。独立专题另设入口，直接选择资料、研究人群和分析要求，不先生成完整报告；仍可按需把专题作为完整报告的附加章。

专题支持上传大纲、手工编辑或依据研究问题生成建议大纲。将大纲拆为可核对的分析项，预览题项匹配、研究对象、统计口径和资料缺口，确认后再运行。正文标题可以合并相近主题，但不能因默认字数或小节上限遗漏必答项。每项应能追踪到正文、资料不足、待确认口径或执行失败等明确状态。

首个试点可沿用“某行业毕业生专项分析”。先统一行业、届次及群体筛选，再统计就业质量、专业匹配、能力需求等指定指标。正文给出总体判断、关键差异、培养含义及必要建议。正文简洁，具体统计口径、样本和证据留在内部核验，确需说明时集中呈现。

专业规范分层执行：

- 指标字典定义正式名称、选项合并、分母、适用人群、缺失处理和常模比较条件。数值由程序计算，正文、图和表共用同一结果。
- 将解读案例整理为有适用条件的正反例，约束完整指标名称、评价主体、判断力度和建议表达；示例数字与其他学校事实不作为本校证据。
- 以学校事实库检查已有举措及实施状态，建议应指出现有工作的具体改进空间，不能把已开展工作重新包装成建议。
- 验收时检查所有必答项、数值和判断是否有依据；续图统一尺度与排序，动态显示实际可比届次，不将缺失补为零。

## 三、加入定向搜索、学校事实库与跨年复用

会议将官网搜索纳入建设范围。第一版先覆盖学校公开信息，不把开放网络搜索、机构常模和私有数据库接入捆绑成一个大功能。

1. 提供定向检索配置：学校名称、已核验官网域名、主题、时间范围及资料类型。任务运行时查询学校官网、公开讲话和战略规划等，允许用户指定本次关心的问题。
2. 对命中的材料记录标题、来源链接、发布日期、采集时间和适用范围，优先提取可引用片段；将网页内容视为证据数据，不执行其中的指令。识别同名院校、转载、过期资料和未经证实的说法。
3. 搜索结果可归档，提炼办学定位、已有举措、实施进度、覆盖范围和证据。最新讲话体现的关注点应标为待核实的分析线索，与学校明确提出的问题分别记录；不能将讲话中的计划当成已落实工作。
4. 次年复用时检查资料年份、时效和适用范围。新版本与历史记录并存，不能用旧届事实替代新届结果。学校事实可沿用，届次指标仍需按本次数据重新确认。
5. 后续再增加同类型院校的公开方案检索，按院校类型、学科、问题和实施条件筛选，仅作为参考方案。机构私有案例和常模需授权及口径确认后接入。

跨年“记忆”主要由应用层的资料、学校事实、指标口径、历年结果与经审核建议形成，不依赖模型记住上次对话。可以先在内部存储中实现版本管理和检索；私有推理另行验证，两项工作可分别验收。

## 四、把深度诊断扩展到多源数据

将就业、招生、教学、课程与实践评价的数据按获准用途在本地关联。先确认统一的届次、学院、专业编码和数据粒度；只有具备合法授权、可靠关联键时才进行个体层连接，否则使用同口径的专业或群体汇总。记录缺失、未匹配、重复和关联覆盖情况。

分析按“发现问题 → 分组验证 → 排查可能原因 → 结合学校现状提出措施 → 指定验证指标”组织。例如，某专业离职率偏高时，先区分主动与被动离职，再检查离职原因、专业相关度和岗位适应情况。证据只能支持相关性时，保留为待验证原因，不作确定性归因。

“处方”应能说明具体改进环节、行动、适用对象和如何判断是否有效。初期挑选一项有完整数据和专家参考结论的诊断场景验证，不要求一次覆盖所有垂域。

## 五、验证私有模型与混合调用方案

纪要记载的“千问3.8 27B”是候选方案，准确型号、部署条件及质量均待验证。用同一批脱敏用例比较本地候选和当前可用 API：指标口径遵循、长文结构、要求覆盖、建议适配、工具与结构化输出、耗时、显存及并发表现。不能仅凭参数规模或连接成功判断能否承担深度诊断。

混合调用按数据敏感级别路由。原始问卷、身份字段、私有常模及未经批准的校本材料留在内部，统计、关联和必要的生成在本地完成；外部模型仅接收明确允许外发的脱敏材料或汇总结果，检查小样本和组合字段的再识别风险。敏感任务不能因本地模型故障自动回退到外部接口。

规模化前单独评估企业账号：核对企业使用条款、限额、并发和数据留存条件，按完整报告和独立专题分别记录模型输入、输出、思考用量与失败重试，结合实际账单估算单篇及月度成本。没有实测用量前不承诺费用。

## 六、实施顺序与试点交付

| 顺序 | 交付 | 验收重点 |
| --- | --- | --- |
| 第一批 | 解析预检、失败诊断记录、核心指标口径与解读案例验收清单 | 双届样例、正确分母、错误能定位 |
| 第二批 | 独立专题、动态大纲、必答项检查；学校事实先支持上传资料整理，并做一所学校的官网搜索归档试点 | 目标人群一致、问题答全、建议与学校事实相符、来源可追溯 |
| 第三批 | 跨年资料复用、同类方案检索、成熟规则推广至完整报告 | 不混用届次、图表尺度一致、正式报告结构和表达符合规范 |
| 条件具备后 | 私有候选模型与混合路由、多源私有数据诊断、企业用量与成本评估 | 有授权数据、部署环境和验收样例；敏感数据不外发；结论可验证 |

会议提及的约两周可作为首轮试点评估节点：选一个专题、一批双届样例、一所学校官网和若干解读案例，对照人工结果评估可用性。深度诊断是否达标以专家评审和证据为准。开发按对应修改做针对性验证；不为每项改动反复生成整份报告。

需要麦可思配合确认：首批试点专题与验收标准、指标字典及选项合并规则、可授权使用的脱敏数据和案例、常模口径、允许外发的材料范围，以及候选私有模型的准确标识和部署条件。

需求来源：两轮反馈、10月20日会议纪要、《解读规范参考》和《解读案例-20260515》。
