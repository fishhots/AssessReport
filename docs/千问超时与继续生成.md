# 千问超时与继续生成

排查日期：2026-10-03。

## 本次原因

任务 `462ec518-8952-4ddc-b867-9e8430441071` 使用 `qwen3.8-max`，额外深度分析为自动，思考预算4096。第二、三、四次尝试均在“第五章 教学培养反馈”的 `compose` 阶段于90.08、90.11、90.05秒超时。分析阶段使用流式调用，正文阶段此前使用非流式调用，且默认响应等待仅90秒。第五章分析请求输入约8.2万Token，正文输出较长，90秒等待不足。日志没有证明模型平台拒绝处理请求。

第四次尝试已完成第一至第四章，并成功取得第五章分析。成功请求累计输入540309、输出62901 Token；最后超时请求的用量未返回，不含在这两个数字中。原“重新执行”会从头生成，重复发送前面已经完成的内容，所以多次尝试会累计消费。此前执行请求已经关闭SDK自动重试，本次重复成本主要来自多次从头执行。

客户端超时不会撤销已经完成的处理。阿里云说明流式与非流式按同样规则计费，中断时输出Token计至服务端收到终止前的已生成部分；实际金额需要查看平台账单。[官方说明](https://help.aliyun.com/zh/model-studio/stream)

## 修复行为

- 千问所有阶段均使用流式传输，包括关闭额外思考时的正文和工具调用；最终请求用量使用 `stream_options.include_usage` 获取。前端仍按章节显示进度，流式片段由智能体内部组装为完整章节。
- 千问报告调用区分连接等待和无数据等待：连接最多30秒，无数据等待至少180秒；持续收到数据时允许继续生成，单次累计最多600秒，并检查任务总时限。连接测试仍保持短超时。
- 千问每个返回片段检查任务取消或时间预算，超出后关闭SDK响应上下文。调用和连接测试均不自动重试。
- 已完成的校验章节与公开分析写入本地检查点。“继续生成”匹配同一资料、写作规则、用户要求和模型配置后复用；已完成分析后的正文超时，不必再次支付相同分析调用。章节中的图表依据已核验的数据在新目录重绘，保持导出文件完整。
- 格式或内容生成仍未完成的章节不作为已完成章节锁定。检查点无效、损坏或输入不匹配时不复用；改变密钥不会改变已完成内容的适用性。
- 调用日志标记成功/失败、错误类别和用量是否取得。失败且没有用量为 `unknown`，不记录为零费用，不保存原始异常、密钥或私有思维链。
- 生成任务在启动时固定模型配置，使检查点匹配信息与分析、正文实际使用的模型保持一致。
