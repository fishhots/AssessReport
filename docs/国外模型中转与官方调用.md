# GPT、Claude、Gemini：智增增中转与官方直连

在前端“模型设置”中，打开 GPT、Claude 或 Gemini 的设置，选择“智增增中转”或“官方直连”。两种方式的模型名称、地址、密钥、额外参数和思考设置分别保存。

首次配置这三家模型时默认显示智增增中转地址。已有配置作为官方配置保留，不自动换地址或将原密钥用于中转。切换只是查看和编辑，点击“保存配置”后才改变新任务采用的调用方式。

## 地址与接口

| 模型 | 智增增中转的接口基础地址 | 官方直连的接口基础地址 |
|---|---|---|
| GPT | `https://api.zhizengzeng.com/v1` | `https://api.openai.com/v1` |
| Claude | `https://api.zhizengzeng.com/anthropic` | `https://api.anthropic.com` |
| Gemini | `https://api.zhizengzeng.com/v1` | `https://generativelanguage.googleapis.com/v1beta/openai` |

填写基础地址即可，程序会拼接实际请求路径。地址允许修改，例如使用平台文档列出的备用节点。

GPT 中转使用平台提供的 OpenAI Chat Completions 格式，输出长度采用 GPT 的 `max_completion_tokens` 参数；GPT 官方继续使用 Responses 格式。思考参数按两种请求格式分别适配，中转请求不会携带仅属于 Responses 的 `reasoning`、`include` 等字段。

Claude 使用原生 Messages 格式，实际中转请求为 `/anthropic/v1/messages`，保留原有普通与深度分析阶段的参数适配。

Gemini 使用 OpenAI 兼容文本格式，实际中转请求为 `/v1/chat/completions`。平台也提供 `/google` 原生 Gemini 接口，但本系统当前选择其兼容文本接口，延续现有 LangChain 文本报告流程。

上述中转地址和接口格式依据智增增的[地址说明](https://doc.zhizengzeng.com/doc-4296789)、[模型与端点说明](https://doc.zhizengzeng.com/doc-3979947)以及 [Claude 接入说明](https://doc.zhizengzeng.com/doc-6799584)。GPT 官方调用延续 [OpenAI SDK 的 Responses 方式](https://developers.openai.com/api/docs/libraries)。文档核对日期：2026-10-04。

## 配置步骤

1. 打开对应模型设置，选择“智增增中转”。
2. 填写智增增平台支持的实际模型名称，使用弹窗里的“查看模型列表”链接核对。模型名称始终允许编辑。
3. 保留默认中转地址，或填写平台提供的备用节点对应基础地址。
4. 填写在智增增平台申请的 API Key。首次配置中转方式时需填写中转 Key；不会借用已保存的官方 Key。
5. 点击“保存配置”。需要真实连通性验证时，点击“保存并测试”。测试会请求所选模型。

恢复官方方式时，选择“官方直连”，会加载该方式保存的配置；未保存过则显示官方基础地址，需要填写对应厂商 Key。选中后保存即可。

## 中转等待时间

GPT、Claude、Gemini 的中转报告调用统一使用 10 分钟等待，覆盖章节分析、正文生成、补写及修订，采用流式接收。连接建立最多等待 30 秒；单次流式生成也有 10 分钟上限，收到数据后继续检查任务终止状态和总任务时限。连接测试单次最多等待 60 秒，与正式报告分别设置。

部署时可在 `agent-service/.env` 配置 `ASSESS_RELAY_MODEL_TIMEOUT=600`（报告调用，允许 90–1200 秒）和 `ASSESS_RELAY_TEST_TIMEOUT=60`（连接测试，允许 5–90 秒），修改后重启智能体服务。默认值已生效，无需修改前端的模型配置。官方直连及国内模型沿用原有等待设置。

超时不会触发 SDK 自动重发。继续生成复用与当前资料、模型和写作配置一致的已完成章节及公开分析缓存，同时恢复未完成章节的正文、已完成的修订和补写批次。恢复后重新校验，只调用尚未完成的步骤。图表在当前尝试目录重新绘制。

额外分析步骤返回平台暂时不可用（503等服务端错误）时，记录错误并直接依据已核验资料生成正文，不重发该分析请求。认证、余额、限流、超时仍明确报错；正文请求本身失败时保存现有进度，等待用户继续。此处理适用于使用独立分析流程的各模型，不改变用户的思考模式配置。完整说明见[中断后的正文与补写恢复](中断后的正文与补写恢复.md)。

延长本地等待可以减少客户端提前超时；中转平台或模型服务自身的超时、断线仍可能中断请求，已处理部分仍可能计费。

## 配置、任务与验证

密钥继续加密存储，读取配置不返回明文。配置切换和保存有版本检查，旧弹窗不能覆盖另一窗口较新的修改。任务启动时已取得的配置继续用于该任务，后续保存影响新任务。

Qwen、DeepSeek、GLM 的现有设置与调用流程保持原方式。

本次通过模拟传输验证实际 SDK 请求路径、认证头、分析与成文阶段的参数，并检查旧数据库迁移、两种配置独立存储、空密钥保留和版本冲突。没有使用用户密钥调用中转平台，也没有产生付费模型测试；真实账户的权限、余额与服务连通性需要在填写 Key 后通过“保存并测试”确认。

验证结果：智能体全量测试 259 项通过、1 项跳过；最终 GPT 输出参数适配后，相关回归测试 90 项通过。Spring Boot 后端 11 项测试通过，Vue 前端构建通过，已在浏览器验证三家模型的调用方式切换与独立配置加载。

中转等待时间更新后，智能体全量测试 312 项通过、1 项跳过。新增测试使用 SDK 模拟传输，覆盖三家中转各阶段的超时设置、超过原90秒限制的接收、终止及总任务时限、断线关闭、用量统计、单次请求不自动重发，并验证官方配置保持原行为；未调用付费模型。

后续流式错误分类更新后，全量测试340项通过、1项跳过。Gemini 第三章分析的同一请求现已完整成功并缓存，可继续生成；旧失败日志缺少具体错误字段，无法确定当时的上游原因。此次真实核查发起3次模型调用，详见 [中转流式错误与 Gemini 续写核查](中转流式错误与Gemini续写修复.md)。
