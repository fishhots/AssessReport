# 联网搜索模块

基于 DeepSeek 官方 **Search / Fetch** 接口，让智能体自动访问学校官网获取公开信息，替代人工预先收集领导讲话、战略规划等资料。

对应三项要求：

| 要求 | 实现方式 |
| --- | --- |
| 智能体自动访问学校官网，不依赖人工预先收集入库 | `WebSearchService` 按结构化指令调用 Search（`need_content=true` 直接取回网页正文）与 Fetch；报告任务执行时程序化预取；工具循环模型还能按需自主检索 |
| 搜索结果自动形成库存档，供后续复用 | Python 侧 `WebArchive`（SQLite，按用户隔离）+ Java 侧把正文写成 `.txt` 文件并登记为 `Material`；相同指令缓存期内直接复用，同一 URL 只存一份 |
| 明确的搜索指令接口，指导定向检索特定学校信息 | `WebSearchDirective` 契约（学校 / 官网域名 / 主题 / 关键词 / 年份 / 条数）+ 6 个主题模板 + 指令预览接口 + 4 个智能体工具 + 专用提示词 |

## 数据流

```
前端「联网检索」或报告任务指令
        ↓  POST /api/web-search/run 或 JobRequest.webSearch
Spring Boot WebSearchController
        ↓  POST /web-search/run（内部 API，带 X-Workspace-User）
Python WebSearchService
        ↓  命中归档缓存？→ 直接返回，不联网
        ↓  未命中 → DeepSeek Search /v1/tools/search（need_content=true）
        ↓  按 site 域名过滤 → 必要时 Fetch /v1/tools/fetch → 正文清洗
        ↓  WebArchive.save（URL 去重、批次缓存）
        ↑  返回归档条目（含正文）
Java WorkspaceService.importWebPages
        ↓  写 .txt 文件到 uploads/ + 登记 Material（workspace.json 唯一写入者）
        ↓  回填 /web-archive/materialized
资料库里的新资料 → 后续报告任务可直接勾选；本次任务则注入 Corpus 形成 Evidence
```

Docker 部署时 agent 对 `backend-data` 是**只读挂载**，因此归档正文必须经 HTTP 回传给 Java 落盘，Python 不直接写 uploads。

## 指令契约 `WebSearchDirective`

前端/后端传 camelCase，Python 用 `pydantic` 严格校验（`extra=forbid`）。

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | false | 任务内自动预取开关；手动执行检索时忽略 |
| `school` | string | 空 | 学校名称，必填（任务内自动取 `JobRequest.school`）；限 100 字 |
| `site` | string | 空 | 学校官网域名或含域名的 URL，如 `bistu.edu.cn`；填写后自动加 `site:` 并**丢弃站外结果** |
| `topics` | string[] | 领导讲话 + 战略规划 | 主题 ID，最多 6 个 |
| `keywords` | string | 空 | 补充关键词；禁止包含 `site:` 等搜索操作符 |
| `category` | DATA/SPEECH/REFERENCE/null | null | 归档类别；留空时按主题自动（领导讲话→SPEECH，其余→REFERENCE） |
| `maxResults` | 1–10 | 5 | 每个主题返回的搜索结果数 |
| `maxPages` | 1–30 | 8 | 本次最多归档页数，另受 `ASSESS_WEB_SEARCH_MAX_PAGES` 硬上限约束 |
| `yearFrom` | 2000–2100/null | null | **资料起始年份**（含），作为检索关键词加入搜索式 |
| `yearTo` | 2000–2100/null | null | **资料结束年份**（含），与起始年份一同参与检索与结果过滤 |
| `includeUndated` | bool | true | 是否放行无法判定年份的网页；默认放行（官网页面大多不标发布日期），取消勾选可严格排除 |
| `afterYear` | 2000–2100/null | null | 旧版「起始年份」，等价于只设 `yearFrom`，保留兼容 |
| `refresh` | bool | false | 忽略归档缓存重新联网 |
| `fetchContent` | bool | true | 搜索结果正文过短（<400 字）时补抓 Fetch |

年份可填 `2025` 或 `25`（两位简写自动补成 2025）；**起止填同一年即只获取该年资料**，例如 `yearFrom=25, yearTo=25`。只填其中一个时，另一个按同一年补齐；起始年份不能大于结束年份。

### 主题模板

| ID | 名称 | 检索词 | 默认类别 |
| --- | --- | --- | --- |
| `leadership_speech` | 领导讲话 | 党委书记 校长 讲话 人才培养 高质量发展 | SPEECH |
| `strategic_plan` | 战略规划 | 事业发展规划 十四五 规划 战略目标 | REFERENCE |
| `school_profile` | 办学定位 | 学校简介 办学定位 办学特色 发展目标 | REFERENCE |
| `talent_training` | 人才培养 | 人才培养 培养目标 专业建设 教学改革 | REFERENCE |
| `quality_report` | 质量报告 | 本科教学质量报告 毕业生就业质量报告 | REFERENCE |
| `discipline_reform` | 学科与改革 | 学科建设 教育教学改革 一流专业 课程建设 | REFERENCE |

生成的搜索式形如（`yearFrom=2024` 时）：

```
北京信息科技大学 2024 党委书记 校长 讲话 人才培养 高质量发展 site:www.bistu.edu.cn lang:zh
```

始终控制在 DeepSeek 要求的 128 字符内，优先保留学校名与 `site:` 限定。可在「联网检索」页面点「预览检索指令」查看，不联网、不计费。

## 年份区间：只获取指定年度的资料

**不使用 `after:` / `before:` 时间操作符。** 原因有两点：DeepSeek 的 `after:2025` 语义是「2025 年之后」（不含 2025 本身），单年区间 `after:2025 before:2026` 会退化成空区间；更关键的是官方 `results.date` **未知时为 `null`**，而学校官网页面绝大多数不标发布时间，带时间操作符会把这些页面成批排除。这正是「2025→2025 搜不到、2025→2026 反而有结果」的原因——后者命中的其实是 2026 年的页面。

现在的策略是两层：

1. **年份作为检索关键词**：目标年份写进搜索词，让引擎召回该年度相关内容，但不做任何时间过滤，无日期页面也能被返回。
2. **结果侧判定**：每条结果在归档与 Fetch **之前**，从 `date`（RFC 3339）、标题、URL 路径中提取年份；能判定年份且全部落在区间外则丢弃；完全无法判定年份的页面**默认放行**（取消勾选「包含未标注年份的页面」可改为严格排除）。被丢弃的数量在结果区显示为「按年份过滤 N 页」。

因此 `25 → 25` 时，2024 年的讲话会被排除，2025 年和无日期页面会保留。年份判定**不用正文和摘要**——官网页面常同时出现规划起止年与往届数据，用正文判定会误伤。标题或 URL 含多个年份时，任一落在区间内即保留（例如「2023—2025 规划」在 2025 区间内可用）。URL 里的 `/2025/0512/`、`t20250512_123.html` 这类紧凑日期也能识别，12 位文章 ID 不会被误判成年份。

| 场景 | 行为 |
| --- | --- |
| 页面 `date=2025-05-01` | 保留 |
| 标题「2023—2025 事业发展规划」 | 保留 |
| `date=2024-05-01`、标题与 URL 都是 2024 | 丢弃 |
| 无 `date`，标题与 URL 都不含年份 | 默认放行；取消勾选「包含未标注年份的页面」后严格排除 |

> 「只获取指定年度」是尽力而为：官网大量页面不标日期，严格排除虽更精确但容易让结果为空。结果为空时先点「预览检索指令」确认年份关键词，再放宽到多年区间或留空年份。年份过滤发生在 Fetch 之前，被丢弃的页面不会产生额外计费请求。

年份区间与检索策略版本会进入 `queryKey`，策略变更后旧缓存自动失效、不会复用旧批次；入库的 `.txt` 抬头含「资料年份」，显示文件名也会带年份标签，便于以后在资料库区分年度。前端「联网检索」页与报告工作台「本次启用」都可设置。

## 给智能体的搜索工具

仅在任务启用联网检索时挂载（见 `EvidenceStore.web_tools_provider`），并追加 `prompts/web-search.md` 的使用约束：

| 工具 | 用途 |
| --- | --- |
| `list_web_search_topics()` | 列出可用主题与类别 |
| `search_web_archive(query, topic, limit)` | **优先使用**，只查归档库，不联网、不计费 |
| `search_school_web(topic, site, keywords, max_results, year_from, year_to, refresh)` | 下发定向检索指令（可指定资料年份区间），抓取并归档 |
| `fetch_school_page(url, topic)` | 抓取指定官网页面 |

工具返回的 `evidenceIds` 与人工上传资料走同一套 `read_evidence` / `search_evidence` / 引用校验链路。官网信息被限定为 SPEECH/REFERENCE 定性依据，不允许当作校本 DATA 统计数值。

**DeepSeek 走无工具思考路径**（`thinking_write`），因此仅有工具是不够的：`workflow.parse` 会在证据入库前执行程序化预检索，把归档正文注入 Corpus，保证两条模型路径都能引用。联网失败只写一条 warning，不阻断报告生成。

## 配置

密钥**默认复用网页「模型设置」里已保存的 DeepSeek API Key**，无需重复填写。Search/Fetch 是官方接口，不走模型配置里的中转地址。

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `ASSESS_WEB_SEARCH_API_KEY` | 空 | 单独指定密钥；优先级高于模型设置 |
| `ASSESS_WEB_SEARCH_BASE_URL` | `https://api.deepseek.com` | 官方 Search/Fetch 基础地址 |
| `ASSESS_WEB_SEARCH_ENABLED` | `false` | 全局开启任务内工具；默认关闭，完全不改变既有报告行为 |
| `ASSESS_WEB_SEARCH_TIMEOUT` | `20` | 单次请求超时（秒） |
| `ASSESS_WEB_SEARCH_CACHE_DAYS` | `30` | 相同指令归档缓存有效期；期内直接复用，不联网不计费 |
| `ASSESS_WEB_SEARCH_MAX_PAGES` | `12` | 单次检索归档页数硬上限 |
| `ASSESS_WEB_SEARCH_MAX_PAGE_CHARS` | `40000` | 单页正文长度上限 |

修改 `.env` 后需重启智能体服务；Docker 在 `.env.docker` 中配置并重建 agent 容器。

**计费**：Search 与 Fetch 按成功请求次数各 5 元 / 1000 次，搜索无结果或失败不计费。`need_content=true` 让一次 Search 就带回正文，通常无需额外 Fetch。「测试连接」会产生一次计费请求。

## 接口

### 前端 REST（需登录）

| 方法 | 路径 | 说明 |

| GET | `/api/web-search/status` | 配置状态、密钥来源、主题列表、归档统计 |
| POST | `/api/web-search/preview` | 只展开指令，不联网 |

| POST | `/api/web-search/test` | 最小连通性测试（一次计费） |

| GET | `/api/web-search/archive/{id}` | 归档正文全文 |

### Python 内部 API（仅 Spring Boot 访问）

`/web-search/status`、`/web-search/preview`、`/web-search/run`、`/web-search/test`、`/web-archive`、`/web-archive/pending`、`/web-archive/{id}`、`/web-archive/materialized`。

### 任务内指令

创建报告任务时传入 `webSearch`（工作台勾选「本次启用」即自动生成）：

```json
{
  "school": "北京信息科技大学",
  "webSearch": {
    "enabled": true,
    "school": "北京信息科技大学",
    "site": "bistu.edu.cn",
    "topics": ["leadership_speech", "strategic_plan", "school_profile"],
    "maxResults": 4,
    "maxPages": 8,
    "yearFrom": 2025,
    "yearTo": 2025,
    "includeUndated": false
  }
}
```

该参数随任务持久化（含在 `ReportTask` 中），重试时保持一致。

## 归档与复用

- 归档库：`agent-service/data/users/{用户ID}/web-archive.sqlite3`（Docker 在 `agent-data` 卷）；按用户隔离。
- 同一 URL 唯一；正文哈希变化时更新内容并**清空入库标记**，让 Java 重新登记资料文件。
- 每组指令以 `queryKey = hash(学校|域名|主题|关键词|年份|条数)` 记录批次，缓存期内重复执行直接返回归档，不联网。
- 归档条目转成 `W-` 前缀 Evidence，带标题、域名、URL 等来源信息（仅供内部取证，正文不得写网址）。
- Java 登记的 `.txt` 资料带来源抬头（标题/网址/主题/抓取时间），可被 `parse_job` 正常解析，之后与普通上传资料完全一样。

## 安全边界

- URL 只接受公网 HTTP(S)，拒绝 localhost、内网 IP、凭据型 URL、控制字符；`site` 非空时严格校验结果域名（含子域），站外结果丢弃。
- 上游错误只映射为固定类别码，不把响应原文（可能含密钥或学校数据）写入界面或日志。
- 密钥不出现在任何 API 响应、任务快照或归档正文；状态接口只返回密钥来源。
- 归档正文有长度与页数上限，避免单次检索无限放大。
- 联网失败降级为「按已上传资料取证」，不会让报告任务失败。

## 验证与排错

```powershell
cd agent-service
.\.venv\Scripts\python.exe -m pytest tests/test_web_search.py -q
```

| 现象 | 排查 |
| --- | --- |
| 状态显示「未配置」 | 到「模型设置」保存 DeepSeek 的 API Key（须为官方密钥，中转 Key 无法调用 Search/Fetch），或设置 `ASSESS_WEB_SEARCH_API_KEY` |
| 401 / 402 | 密钥无效或账号余额不足；Search/Fetch 与模型调用共用账号余额 |
| 结果为空 | 域名填错或过窄；留空 `site` 全网检索，或用「预览检索指令」检查搜索式。单年区间为空时先放宽到多年区间（官网页面多不标发布日期）；已不再使用 `after:` / `before:` |
| 结果里全是「按年份过滤 N 页」 | 年份区间过窄，或页面只标了区间外年份；放宽区间或留空年份，也可取消勾选「包含未标注年份的页面」反向核对 |
| 提示「起始年份不能大于结束年份」 | 交换起止年份；`25` 与 `2025` 等价 |
| 429 | 账号级 QPS（Search 100 / Fetch 25）或目标域名限流，稍后重试 |
| 归档未出现在资料库 | 点「同步归档到资料库」；检查 Java 与 Python 之间的 `ASSESS_SERVICE_TOKEN` 是否一致 |
| 报告里没引用官网信息 | 确认任务 `webSearch.enabled=true`，或在资料库勾选已入库的 `.txt` 资料；查看任务目录 `web-search.json` |

## 已知限制

- 报告仍要求至少一份可读取的上传资料（`JobRequest.materials` 非空），官网信息用于补充领导讲话/规划等背景资料，不能替代问卷校本数据生成前八章统计。
- 扫描版 PDF、需要登录或 JS 渲染的官网页面，Fetch 可能无法提取正文；此时保留搜索摘要。
- 年份判定依赖发布时间、标题与 URL 中的年份，不读取正文；官网若既不标日期也不在标题/网址写年份，严格模式下会被排除，需手动勾选放行。
- 归档缓存按指令维度复用，不会主动轮询官网更新；需要最新信息时勾选「忽略归档缓存」。
- 升级后执行资源指纹（新增模块、提示词）变化，未完成任务的历史检查点不会复用，属预期行为。
